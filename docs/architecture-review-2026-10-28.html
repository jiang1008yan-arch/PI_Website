Problem
ticketService 名义上是唯一 writer，但 7 处绕过它；createTicket 的 INSERT ticket 和 INSERT note 是两次 .run()；Feishu 确认工单串了 7 次以上独立写入，分类失败还被 .catch(() => false) 吞掉，中途失败会留下半张工单。
Solution

Wins

  • create + note + type + fault 原子
  • leverage：web、Feishu、cron 共用一个 interface
  • 测试直接打 workflow interface
  • TicketError 不再泄漏进 _shared.ts

Top recommendation

1 · Ticket workflow

Ticket 是项目里增长最快、改得最勤的领域，而它的写入路径正是 PI 在 piWorkflow 出现之前的样子：写入者分散、不原子，还有一处已经违反了 “every change is logged”。PI 一侧已经证明了这种形状可行（plan → 一个 batch），四个 int test 已经锁住 HTTP 行为，所以在 “功能不受影响” 的前提下，它是风险最低、回报最高的一项。做完之后，候选 3（Ticket request）的 confirm 就可以一次原子提交。

建议顺序：1 → 3 → 2 → 5 → 4 → 6 → 7（7 涉及数据可见性，也可以单独提前做）→ 8
